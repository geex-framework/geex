# Enumeration 动态枚举专项

`scopeId`: `enumeration-dynamic`. 本专项覆盖 Enumeration 的动态构造/可选属性定义/家族实例复用/静态发现/别名/反射入口与 JSON/BSON 转换. 公共契约见 [Enumeration API](../../enumeration.md); 回归断言位于 `Geex.Tests/UnitTests/EnumerationDynamicTests.cs`.

规则 `ENUM-DYNAMIC` 依据用户已确认的动态枚举设计与修复范围. Runner 执行前从固定测试类的每个无参数 `[Fact] public void/Task` 方法预登记唯一实例, 保存源码快照/方法定位/预期引用与完整清单; 未发现或跳过的必测方法不得通过. 新增测试方法自动进入下一次运行的冻结范围, 不根据成功输出反推用例列表.

`ENUM-DYNAMIC` 的专项规则与覆盖边界:

- 动态构造优先使用请求具体类型声明的精确 `(string name, string value)` 构造, 支持任意可见性. 未提供该构造时, Enumeration 派生类型使用 public 无参构造并设置 Name/Value. 不猜测单字符串/可选业务参数, 不绕过构造函数; 构造失败和非法结果不得进入缓存. 独立 `IEnumeration` 通过二参构造自行初始化只读 Name/Value.
- 每个实际 `Enumeration<TRoot>` 家族按 Value 复用同一实例. 根类型/子类型/反射/JSON/BSON 入口使用同一家族, 保留请求具体类型. 已有实例类型兼容但不同时记录警告并复用, 不兼容时拒绝. 同 Value/不同 Name 保留原 Name 并警告; 同 Name/不同 Value 拒绝.
- 可选 `Enumeration<TEnum, TDetails>` 由类型显式提供未知属性定义. `Definition` 快照包含 `Details`/`IsComplete`. 未完整定义的动态实例记录 Warning; 显式 `Define` 补全同一实例, 一次性发布完整快照, 不改变引用/Name/Value. 相同完整定义可重复提交, 不同定义拒绝且保留原状态. 验证不依赖 CLR 默认值推断完整性.
- 动态回退前发现已登记程序集中的后代类型及其静态成员. 同类型初始化重入时登记已经赋值的 public static readonly 字段和 public 自动属性 backing field, 不执行计算属性 getter. 程序集重新发现保留既有静态/动态实例和别名.
- 同次批量别名先完整校验再登记, 冲突不得留下部分绑定. 已成功解析的规范实例不因别名冲突回滚. 同 Value 的并发解析/补全保持实例唯一和定义一致.
- 权限根类型/模块类型/嵌套子类型的二参构造接收完整 Value, 保持前缀与派生字段一致; 单参构造继续接收已有约定的短值. 普通无附加属性枚举保持零配置.
- JSON 写 Value; 读取兼容已有 Value/值别名/旧 Name. 名称和值命中同一实例时复用, 命中不同实例时拒绝歧义, 均未命中时才创建. BSON 保持 Value 表示. 定义快照不随字符串序列化持久化.

实例身份保证适用于同一 `Enumeration<TRoot>` 家族的受控查找/定义入口, 不跨不同泛型家族合并缓存. 自动发现范围限于已登记程序集, 不扫描或加载所有程序集. 直接 `new` 仍会创建新对象, 构造函数不能返回已有对象引用. 未采用可选属性定义基类的业务枚举保持其构造要求, 本专项不为 Settings/审批实体类型引入未知业务默认值. GraphQL ENUM 仍受 schema 声明范围约束. 以上是专项验证目标, 是否通过须读取对应运行的机器记录.

开发自测与独立专项复测使用相同冻结方式. 每次单独创建 runId, 不复写既有证据. 基线涵盖专项源码/测试源码/引用项目源码与项目文件/依赖资产/SDK/构建产物哈希. 关键实现/公共契约文档/测试源码保存快照, 完整项目依赖图中的源码进入输入身份清单. 构建前冻结输入, 构建后记录实际依赖资产及产物, 测试前冻结 baselineId; 测试后核对输入/资产/产物是否变化. 配置只记录边界或哈希, 不复制应用配置内容.

测试使用真实框架代码及进程内合成对象, 不启动数据库或应用宿主. UI/真实 HTTP 链路/部署/升级恢复/性能/稳定性不在该批次范围内, G-08/G-09/G-10 明示未评估. 并发功能回归不代表容量/性能/稳定性验收. 本范围结果不代表全项目验收, `ACCEPTANCE` 参数也不自动证明独立审查完成.

原始 TRX 保留真实执行 ID/起止时间/原始状态/失败输出. 未启动实例的 `attempts` 为空且 `finalExecutionId` 为 null. 重复执行/未知状态/缺失用例/构建失败/身份漂移均阻止自动通过. 本入口不自动重试, 不推断缺陷已关闭.

每个运行的 `defects/issues.json` 是该次失败与阻塞原因台账, `runner/error-collection.json` 明示采集范围和数量, `runner/validation.json` 记录本次格式/引用/哈希检查. 本工具提供专项记录检查, 不声称实现跨运行全量门禁或完整 G-01~G-10 验收平台.
