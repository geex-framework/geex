# 测试编写指南

本页只说明测试代码和执行脚本的通用写法. 适用阶段/证据格式/验收标准见 [Geex 项目 AI 测试硬性规范](../../docs/Geex项目AI测试硬性规范.md).

## 用例设计

- 从已确认的需求/公开契约推导输入与预期, 再选择测试入口. 不把当前实现自动当作正确答案.
- 优先在能验证目标行为的最小层级编写测试. 跨组件/接口/持久化的行为在对应集成层验证, 明确哪些依赖是真实实现/哪些使用替身.
- 按影响范围选择正常路径/边界值/非法输入/失败分支. 负向用例同时验证预期拒绝和副作用, 避免只检查抛出了任意异常.
- 修复缺陷时补充能够暴露原错误的回归断言. 不为凑数量编写仅复述实现/检查方法存在/匹配源码文本的行为测试; 有明确结构契约时, 结构检查应单独标明目的和边界.

## 组织与命名

- 沿用所属模块已有的测试项目/目录/框架, 将用例放到相应行为附近. 不按临时任务或补丁新建测试项目.
- 用例名描述被测行为/触发条件/预期结果, 失败时能够直接定位场景.
- 一个用例聚焦一个行为, 可以同时断言该行为的返回值/状态和副作用. 避免把多个互不相关的流程串成一个用例.
- 同一规则的多组输入可使用参数化测试, 每组参数必须能独立定位失败. 不同前置条件或预期语义应拆成不同用例.

## 用例结构与断言

按 Arrange/Act/Assert 组织, 不需要机械添加分段注释:

1. 准备明确的输入/前置状态/依赖和独立预期.
2. 调用实际待测入口完成目标动作.
3. 断言可观察结果及必要副作用.

预期值使用可独立核算的样本/已确认公式或固定数据, 不调用被测函数生成 expected 再与实际值比较. 断言应指出字段/参数/预期与实际差异, 避免只检查结果非空/没有抛错/操作返回成功.

异常测试检查契约要求的错误类型/错误码及状态变化. 持久化测试在操作后重新读取数据; 公共接口测试通过该接口完成目标动作, Fixture 仅准备非测试目标的前置条件. 不依赖私有字段或内部调用顺序, 除非这些细节本身就是明确的测试目标.

## 数据与依赖隔离

- 每个用例显式建立前置条件, 不依赖其他用例的执行顺序或残留数据. 共享 Fixture 只共享可安全复用的环境, 可变状态仍需隔离.
- 时间/随机数/外部响应使用可控制的输入; 需要随机数据时固定并记录种子. 隔离资源使用唯一标识, 断言不依赖偶然生成的值.
- 替身用于控制测试边界外的依赖. 被验证的行为必须来自真实被测代码, 不同时模拟行为本身及其预期结果.
- 临时文件/连接/进程/测试数据由创建它们的用例或 Fixture 负责释放. 清理放在可靠的 finally/Dispose/框架清理机制中, 限定到本次创建的资源, 保留失败诊断所需证据.

## 异步与并发

- 等待所有影响断言的异步操作完成, 让异常传播到测试框架. 不启动未等待的后台任务后直接判定通过.
- 等待可观察条件并设置超时, 超时时记录当前状态. 不依赖固定 sleep 猜测操作已经完成.
- 验证竞争条件时使用屏障/信号或可控制的依赖安排交错, 明确断言一致性和副作用. 并发正确性测试与性能/稳定性测试分别设计.
- 不用自动重试掩盖不稳定结果. 重试需要保留原失败/全部尝试和原因, 不能把最后一次成功直接当作问题已解决.

## 测试辅助代码与执行脚本

- 只提取稳定重复的准备/清理逻辑. 辅助方法的输入和资源所有权应清晰, 不隐藏影响用例语义的默认条件.
- 执行脚本使用 PowerShell 7, 显式处理工作目录/参数/外部命令退出码和资源释放.
- 先构建待测项目及必要依赖, 构建失败时阻止依赖测试. 测试命令已包含构建时不重复构建; 对没有构建步骤的测试说明依据, 不使用旧产物补做验证.
- 执行前明确计划与过滤条件, 执行后核对实际发现的用例. 零用例/漏发现/跳过/中断必须显式报告, 不能仅按进程退出码判定通过.
- 为每次运行和工具调用隔离输出, 保存原始日志/测试报告/失败诊断. 汇总从实际记录生成, 不覆盖历史结果; 具体格式遵循测试规范.

## 维护

行为契约变化时同步调整相关用例和预期, 普通实现重构优先保持行为测试有效. 通用编写方法变化时更新本页; 具体功能/脚本清单/单次修改和运行结果不写入本页.
